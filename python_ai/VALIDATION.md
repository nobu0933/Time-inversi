# 検証記録

## 2026-10-20：学習過程の再検証

Windows / Python 3.14 / PyTorch 2.14.1 / CPUで実施。

修正した問題：

- 再開時、自己対戦数・探索数・評価間隔などがコマンドの初期値へ戻っていた。保存済み設定を既定として復元し、明示した実行設定のみ変更するよう修正。
- 再開時に指定したモデル構成・学習率などが黙って無視され、保存設定と実際の処理が食い違う場合があった。復元値と異なる指定はエラーにし、保存する設定も実際の値に統一。
- `--resume`と別の既存学習フォルダーへの`--output`を併用すると、その別の重みを上書きできた。別の既存チェックポイントへの上書きを拒否。
- 学習率・重み減衰の非有限値、勝敗ターゲットの範囲外の値を検出するよう追加。サンプル不足で重み更新を行わない回はその旨を表示。
- Node.jsのないPCでテストが失敗していた。JavaScript照合テストだけを明示的に省略し、Pythonの学習・検証は実行可能に変更。

検証結果：

- 全11テスト成功（Node.jsがある環境、スキップなし）。
- 実際の自己対戦・重み更新・ランダム／簡易AI評価を含む2イテレーションについて、連続実行と「1回保存→再開」の重み全テンソル、リプレイバッファ、NumPy/PyTorch乱数状態、損失・評価結果が一致。小型モデル、CPU、固定シードで検証。
- モデル幅・学習率の不適切な再開時変更、別の既存出力先への上書きを拒否する回帰テスト成功。
- NaN・無限大・範囲外の勝敗ターゲットを拒否するテスト成功。
- JavaScript版との60系列＋追加局面、1,000手以上の遷移照合も成功。
- Node.jsを検出できない状況を模擬し、ルールテスト2件成功・照合1件のみ省略を確認。
- `pip check`：依存関係の不整合なし。

READMEは既存の仮想環境を前提にせず、ダウンロード・環境作成・依存導入・確認・本学習・停止／再開の順に更新。今回、新しい別PCでの再インストールは行っていない。初回の環境構築は下記の前回検証で実行済み。

検証範囲の限界：GPU・別OSでの動作、長期間学習した際の棋力向上は未検証。短い評価局数による勝率は棋力の証明にはならない。現状は逐次自己対戦で、過去の最良モデルとの昇格判定はない。評価より先にモデルを保存するため、評価中に停止するとその回のメトリクスだけ未記録になる場合がある（保存した重みと再開には影響しない）。
